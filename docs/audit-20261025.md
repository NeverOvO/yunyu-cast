# 云屿投屏 0.4.0 代码审计与修复记录

日期：2026-10-25。范围：接收服务生命周期、原生 JNI/UxPlay 桥接、AirPlay 发现、DLNA 发现与事件通知、镜像解码与显示、视频播放器、遥控操作和日志持久化。检查以本地代码为依据，不包含电视实机运行或第三方协议兼容性认证。

## 已修复问题

| 路径 | 原有问题与影响 | 本次处理 |
| --- | --- | --- |
| 原生初始化 | 密钥 / HTTP 或 DNS-SD 初始化失败后仍返回有效句柄，后续操作可能访问未初始化对象 | 失败立即回滚并返回失败，允许安全销毁未完整初始化的 HTTP 服务 |
| 退出与重连 | HLS 就绪等待最长 10 秒，停止时可能在主线程等待；旧状态回调可能干扰新会话 | 断开、停止、销毁前唤醒等待；状态回调串行处理并检查代际；媒体回调保持必要同步；返回只断开当前客户端，监听继续 |
| 原生线程 | 工作线程附加到 JVM 后没有对应分离 | 通过线程局部析构分离本桥接附加的线程，减少反复连接的资源残留 |
| 镜像解码与显示 | 解码器停止异常会跳过释放；GL 异常后运行标记不复位；隐藏时裁切变换滞后 | 确保释放；GL 失败清理并可重新启动；持续更新画面变换；硬件解码器首次运行异常保留一次同画质恢复，重复失败再切换候选 |
| 帧时间基准 | 发送端时间戳跳变或长停顿可能把画面安排到遥远未来 | 偏差超过阈值时重新建立显示时间基准，正常 60fps 间隔保持不变 |
| 视频播放与交互 | 销毁后排队命令可能重建播放器；旧播放器事件和旧点击闭包影响新状态 | 幂等释放并取消排队操作；按播放器身份过滤事件；按钮使用当前回调和真实无障碍点击入口 |
| DLNA 通知与资源 | 失联订阅在 SSDP 定时线程同步通知；慢请求、队列和 socket 清理不足 | 独立有界通知队列；按订阅合并最新状态并公平排队；HTTP 总时限 15 秒、通知总时限 5 秒；关闭时回收连接；修复订阅并发上限及续租竞争；缓存事件 XML |
| AirPlay 发现 | 系统 NSD 与兼容广播抢同一服务名；单项发布影响另一项；主线程等待停止 | 系统 NSD 优先，只补失败项；8 秒回调超时保护及旧代际清理；mDNS 停止不再在主线程 join |
| 日志 | 每条日志同步重写整个文件，媒体回调和界面线程可能等待存储 | 有界内存缓冲与独立串行写线程，500 毫秒合并快照和写盘；清空不被旧写入恢复；销毁排入最后一次保存；导出异常给出提示 |
| 电视页面 | 低高度和大字号下仍可能溢出；遥控焦点失败被误判成功 | 按高度和字号允许滚动；正确判断焦点请求；保留大字、安全边距及自动接收交互 |

默认镜像目标仍为 4K / 60 帧，1080p、2K、4K 和 30 / 60 帧选项保留。镜像错误恢复需发送端下一关键帧；部分发送端可能仍需断开后重新连接。

构建仍有已有的 API 弃用、FlowPreview 标注和 Gradle 弃用提示；本次构建没有失败。上述纯逻辑测试不执行真实 MediaCodec、EGL、Android NSD 或电视系统生命周期。

## 实机边界

尚未确认本版在索尼电视上的连续连接 / 返回重连、后台自动唤起、系统回收恢复、横竖屏切换、长时 4K 播放及大字号实际显示。系统 NSD 完全不回调时，兼容发现约在 8 秒等待加 2.5 秒广播检查后启动；连续临界失败路径更久，不能承诺固定连接时长。

代码已移除已识别的阻塞和资源残留路径，但没有实际流畅度提升百分比、持续 4K60 帧率或零故障保证。
