# 云屿投屏 0.6.3 代码审计

日期：2026-10-28。审计基线为 `5e3ed0d`、`0.6.3-preview.1`、versionCode 14。用户已反馈该版本可用；此反馈对应原发布包，不包含本轮源码修补。

本轮静态审计确认四类问题：一类高优先级输入边界问题，三类中等优先级的资源或状态问题。审计结束时，修补仅写入本地源码；随后用户授权打包发布，执行情况见文末补记。尚无新增修补的电视运行结果。

## P1：AirPlay 镜像数据缺少完整边界检查

基线 `raop_rtp_mirror.c` 直接采用网络包声明的长度分配内存，缺少单包上限和部分分配失败处理；一处失败调用 `exit(1)`，另外两处参数集分配依赖 `assert`。

NAL 循环先读取四字节长度，再判断剩余字节是否足够；零长度 NAL 后仍读取首字节。编码参数解析在确认载荷长度之前访问 `payload + 4`，HEVC 使用固定偏移及递增指针读取三组参数，AVC 根据未检查的 SPS 长度寻找 PPS。部分长度存入有符号 `short`，高位被置位时会变成负数。

异常、截断或超大的镜像输入因此可能造成越界读取、无效内存操作或进程退出。此结论来自调用顺序与长度运算的静态检查，没有复现崩溃，也没有认定存在代码执行能力。

本轮增加单包 16 MiB 上限，在读取参数集之前检查全部相关偏移和长度；长度以无符号读取得到，再存入足够大的整数。NAL 先检查长度字段，再检查 H.264／H.265 最小头部与数据范围。分配失败退出当前镜像处理线程，不再调用进程退出或依赖分配断言；合法的零载荷控制包继续处理。16 MiB 限制针对压缩数据包，不改变 4K／60 帧协商配置，超过上限的发送流会被拒绝。

实现与持久补丁：[raop_rtp_mirror.c](../app/src/main/cpp/third_party/UxPlay/lib/raop_rtp_mirror.c)、[0016 补丁](../app/src/main/cpp/patches/UxPlay/0016-bound-mirror-packets-and-release-stream-resources.patch)。

## P2：镜像断线与周期报告存在资源泄漏

基线代码有三条明确遗漏：读取包头遇到 EOF 时，把连接句柄设为 `-1` 却没有关闭套接字；线程在载荷接收中退出时，没有释放尚未处理完的载荷和待拼接参数集；收到周期状态报告后解析 plist，却没有释放生成的树。反复连接或持续收到报告时，文件描述符和内存可能累积，最终影响新的连接或播放。

本轮在 EOF 路径关闭连接并清理待拼接参数；线程公共出口释放部分载荷和参数集；关闭 FPS 报告显示时不再解析无用 plist，开启时解析后释放；同时补齐远端地址解析失败时的镜像缓冲释放。这些修改与 P1 一同保存在 0016 补丁中，没有长时运行或资源曲线结果。

## P2：系统媒体控制绕过启动回零保护的取消逻辑

基线的 `MediaSessionCompat.Callback` 直接操作播放器。系统或蓝牙媒体按键执行暂停、快进、快退、定位后，未像应用内控件一样取消 `DlnaStartupSeekGuard`。在新影片启动时间窗内，这可能使后续一次真正的回零仍被当成启动对齐而忽略。

本轮将这些入口统一到服务已有的 `setVideoPlaying`、`seekVideoBy`、`seekVideoTo`，使暂停和本机跳转取消启动例外，并保持 DLNA 状态更新。Bilibili 已确认的启动兼容窗口不变。

实现：[AirPlayService.kt](../app/src/main/kotlin/io/github/jqssun/airplay/service/AirPlayService.kt)。

## P2：界面退出后，后台接收日志未写入应用日志

基线日志存储由 `MainViewModel` 创建；服务通过 Activity 设置的 `logCallback` 转发日志。Activity 销毁时清除回调，ViewModel 清理时关闭日志写入器。接收服务继续运行，但这段时间产生的连接和错误记录无法保存到应用日志页。即使新投屏随后唤起界面，唤起前的记录也已经丢失；这会妨碍分析自动连接失败。

本轮改为进程内共享的 `AppLogStore`，服务直接记录，页面观察同一个日志流。存储只保留文件路径，不持有 Activity；沿用最多 2000 条、每条最多 4096 字符、500 ms 合并写入和单线程磁盘写入。界面重建、退出和重新打开不会关闭后台日志写入器，也不会同时创建多个文件写入器。

实现：[AppLogStore.kt](../app/src/main/kotlin/io/github/jqssun/airplay/viewmodel/AppLogStore.kt)、[MainViewModel.kt](../app/src/main/kotlin/io/github/jqssun/airplay/viewmodel/MainViewModel.kt)、[MainActivity.kt](../app/src/main/kotlin/io/github/jqssun/airplay/MainActivity.kt)。

## 审计覆盖和剩余边界

本轮读取并追踪了服务与播放器会话归属、镜像视频与原生音频恢复、JNI、DLNA 控制与事件订阅、发现服务、更新下载和安装包检查、日志存储，以及 0.6.3 的启动回零、日志翻页和分层返回逻辑。未逐行审计全部 FFmpeg、OpenSSL、Media3 等第三方依赖，也未执行漏洞数据库扫描。

更新路径保留包名、递增版本、当前签名集合及摘要检查，安装由系统确认；DLNA 保留请求大小、队列与等待时限、XML 外部实体限制和订阅回调地址约束。本轮在这些已读路径中没有发现新的重大绕过，但这不构成全软件安全保证。

启动阶段首次手动回零与 App 自动对齐仍无法从同样的 DLNA Seek(0) 指令区分。符合兼容条件的首次手动回零可能被略过，第二次照常执行。该已知行为保留，具体条件见[启动重播记录](dlna-startup-20261028.md)。

保持默认画质、音频配置、后台持续接收、返回首页与适老化界面。本轮没有修改签名、版本号或发布附件。新增异常包处理、资源释放和后台日志生命周期均无运行结果；用户对原 0.6.3 的确认不能替代这些修补的设备回归。
