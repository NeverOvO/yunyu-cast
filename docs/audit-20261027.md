# 云屿投屏 0.6.0 代码审计与修复记录

日期：2026-10-27。版本：0.6.0-preview.1，versionCode 11。

本轮按用户要求检查适老化操作、默认配置及持续接收和播放的稳定性。审计覆盖第一方 Kotlin / C++、JNI、UxPlay 补丁和依赖调用边界；未逐行审查全部第三方源码，不等同于第三方协议认证或零故障保证。

## 使用反馈与本轮范围

用户在日常使用中反馈连接和整体稳定性正常，并确认 0.5.4 的 Bilibili 投屏在其索尼电视上正常。该结果仅对应这位用户的设备和场景，不外推至全部手机、电视或视频平台。

本轮保留默认 4K／60 帧、95% 自适应音频、关闭强制低延迟、高级设置折叠和接收常开。升级保留有效个性设置。普通设备探测与实际媒体活动分别处理；真实 AirPlay 媒体会话仍需先在手机停止，才可改用视频 App 的 TV／DLNA 投屏。

## 已识别问题与处理

| 范围 | 问题与影响 | 本轮处理 |
| --- | --- | --- |
| 首次权限与遥控操作 | 未授权自动打开画面时，用户可能不知道退出界面后为何无法自动显示投屏 | 增加大字“去开启／暂不开启”引导；提示进入系统列表先选云屿投屏；已授权跳过，跳过或返回未授权后保留后续路径，首次提示不反复弹出；设置页打不开时安全回退 |
| 弹窗与媒体活动 | 普通 TCP 探测可能被当成正在投屏，影响更新、常亮和画中画；首次提示可能干扰其他操作 | 使用实际媒体活动判断；投屏、PIN、其他权限及更新期间不叠加首次引导 |
| 设备能力声明 | Wi-Fi 硬件要求可能排除仅使用以太网的电视 | 将 Wi-Fi 声明为可选；不改变局域网互通要求 |
| 音频流生命周期 | 旧音频流错误回调可能误重开新音频流 | 按当前音频流身份处理错误，旧回调不改变新流 |
| 延迟采样 | LatencyProbe 满队列覆盖未读槽位，读写线程存在数据竞争 | 调整满队列处理，避免生产者覆盖消费者仍在使用的数据 |
| 连接切换 | 主线程上迟到的末连接断开事件可能停止后续已建立的音频 | 通过 NativeConnectionTracker 区分当前连接状态，旧断开不停止新会话 |
| 音量归属 | AirPlay 音量回调可能干扰 DLNA 静音，切回后可能残留播放器增益；非有限远端音量可能导致转换异常 | 按当前播放协议应用音量，切换时更新播放器增益，并过滤非有限值 |
| 播放结束和错误 | 播放器结束或失败后，原生等待可能仍然持续 | 对终止状态唤醒原生等待，允许会话及时结束 |
| DACP 控制 | 旧会话解析结果或排队命令可能发给另一部手机；资源及总等待时间缺少约束，IPv6 处理不完整 | 隔离会话与排队命令，限制资源和请求总时限，并完善 IPv6 处理 |
| 影片下载 | 初始化异常、共用临时文件及完成保存竞争可能残留文件或错误结束任务 | 独立管理下载任务与临时文件，处理初始化和保存终止路径；取消时清理 MediaStore，服务销毁时释放下载器 |
| DLNA 控制 | 过期 socket 仍可能执行迟到控制，影响后续播放 | 控制执行前检查连接是否仍有效，过期连接不执行指令 |
| 更新恢复 | 不完整恢复元数据或损坏摘要可能导致恢复行为前后不一致 | 恢复前要求元数据完整，损坏摘要不按缺失摘要降级处理；属于一致性防御，原有 APK 签名检查继续保留 |
| 直播播放列表 | 等待播放列表可能长期停留，迟到旧序列可能使进度回退 | UxPlay 0013 增加 15 秒超时重试，限制迟到旧序列回退，并处理 uint64 序列边界 |

原生检查合计 17 组，与 43 项 JVM 测试分别计数。历史版本的检查不计入本轮结果。

模拟器实际检查了以下操作：

- 以遥控方向和确认操作选择暂不开启，查看后续开启路径。
- 拒绝首次提示后重启应用进程，首次提示不重复弹出。
- 打开系统设置页面，未授权返回时显示后续说明。
- 在真实系统设置开关中授权，返回应用后显示已开启。
- 在 960×540 逻辑横屏和 1.5 倍字体下检查最终文案，截图可读、按钮可通过遥控到达。
- 清除应用数据并预先授予显示在其他应用上层权限后，首次打开直接进入首页，不出现首次引导；首页显示默认 4K／60 帧。
- 按返回键退出后，通过 dumpsys 确认 AirPlayService 仍为前台服务（isForeground=true）。该结果只证明检查时服务保持运行，不代表索尼电视长时后台存活。

## Lint 剩余警告

完整 lintRelease 保留 70 个警告和 1 个提示。没有通过新增 baseline 或全局 suppress 隐藏结果，静态扫描通过也不代表所有异常路径均已执行。

本轮复核了主要相关警告：`KEY_ALLOW_FRAME_DROP` 的 SDK 常量标注为 API 31，而该设置行为自 API 29 可用；`ServiceCompat` 调用包含内部版本降级处理；画中画 `sourceRect` 相关项用于动画。持续 WakeLock 与常驻服务引用相关提示在本轮未被证实为确定故障，仍受电视电源管理和系统生命周期影响。上述说明不表示全部警告已清零或所有异常路径已覆盖。

## 仍未覆盖的运行环境

Android 35 平板模拟器用于界面和操作检查，不能代替国行索尼电视的系统权限页面、后台唤起策略、遥控器按键和真实解码器行为。本轮未记录 0.6.0 在索尼电视实机上的连续镜像、相册切换、Bilibili 首次投屏、音画同步及长时播放结果，也未完成安卓手机机型兼容性实测。

本轮检查不提供原生 4K60 持续帧率、连接耗时、资源占用改善百分比或所有投屏 App 兼容性的保证。Miracast、Google Cast 和 DRM 受保护影片仍不在当前接收能力范围内。
