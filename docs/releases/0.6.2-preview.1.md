# 云屿投屏 0.6.2-preview.1

本版调整 DLNA 控制执行和进度读取，补齐 Bilibili 开头重播的定位日志。此前两版的日志没有记录 Seek，短时间内相同控制的日志也可能被合并；现有照片不足以确认重播根因，本版未将该现象列为已解决。

## 本版改动

- 已在播放器主线程上的播放、暂停和跳转直接执行，减少一次额外排队；网络线程仍通过主线程调用播放器。
- DLNA 状态查询读取当前播放器进度和缓冲状态，UI 保留原有定时刷新。播放状态变化后及时同步报告。
- SetAVTransportURI、Play、Pause、Stop 和 Seek 按执行顺序记录，启动期间相同控制的日志不再按一秒间隔合并。
- 记录同一影片地址是否再次提交、Play 是否新建播放器、跳转来源和目标、播放器实际进度变化原因、首帧及画面挂接。
- 日志只包含动作、序号、状态和时间，不包含视频地址、请求头或影片元数据。每次播放器会话的详细诊断上限为 120 条。

同一初始位置的跳转、拖动进度和重新投片仍按指令处理，本版没有增加忽略开头 Seek 或延迟起播的规则。默认画质、音频缓冲、接收常开和遥控使用方式保持不变。

## 电视复现步骤

安装后通过 Bilibili 的 TV／投屏选择云屿投屏，开播前后不拖动进度条，也不先连接其他接收软件。出现重播后继续播放约 5 秒，再停止投屏并打开“连接帮助 → 日志”。保留从“DLNA 已接收影片”到开播后数秒的完整记录。

重点记录包括 `DLNA 执行控制：AVTransport/Seek`、`DLNA Seek 目标=`、`播放器 #… 请求跳转 来源=` 和 `进度变化`。若没有 Seek，则结合播放器创建序号和内部进度变化判断，不能直接归因于发送端。

## 版本与执行范围

versionCode 为 13，包名保持 `com.yunyulai.tvcast`。同证书安装包用于覆盖已有版本。0.5.0 至 0.6.1 可从应用内检查更新，旧版也可通过 U 盘或 ADB 安装 APK。

已完成 ARM32 / ARM64 Release 构建、R8 处理、16 KiB 对齐及原发布证书签名，相关命令退出码均为 0。本轮未新增或运行测试、Lint、额外签名验证、截图、模拟器或真机验证；旧版测试结果不计入本版。照片分析与处理范围见[DLNA 启动问题记录](https://github.com/NeverOvO/yunyu-cast/blob/v0.6.2-preview.1/docs/dlna-startup-20261028.md)。

附件包括 `yunyu-cast-0.6.2-preview.1.apk`、完整源码包、`SHA256SUMS.txt` 和第三方许可说明。原生依赖及 UxPlay 0001 至 0015 补丁未变。
